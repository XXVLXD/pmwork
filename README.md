# Roadly

Интерактивная дорожная карта для менеджера: задачи, зависимости, плавный пересчёт сроков, PDF и редактируемый PowerPoint. Интерфейс на русском, украинском и английском. Проект работает в браузере без регистрации и серверной базы данных.

**[Скачать готовое приложение](downloads/Roadly.zip?raw=true)** — распакуйте архив и откройте `Roadly.html`. Установка программ не нужна. На странице архива в GitHub также можно нажать **Download raw file** (значок стрелки вниз).

## Как пользоваться

1. В готовом архиве откройте файл **Roadly.html** в современном браузере. Если организация запрещает открывать локальные HTML-файлы, используйте размещённую на сайте версию. Это приложение не требует внешних сервисов для работы.
2. На первом экране показан пример. Нажмите **«Новая карта»**, чтобы начать свой проект. Название и целевой срок меняются по нажатию на заголовок проекта.
3. Нажмите **«Добавить задачу»** и укажите название, длительность и ответственного.
4. Чтобы вставить новую задачу между существующими, нажмите **«+» возле предшествующей задачи** либо выберите её в поле **«Вставить в план»**.
5. Перетащите полоску задачи по времени или откройте её для изменения длительности. Связанные задачи плавно переместятся. Выбранную полоску также можно двигать стрелками на клавиатуре: один день за нажатие, с Shift — неделя.
6. **«Зафиксировать план»** сохраняет исходные даты. После изменений тонкие полоски показывают старые даты, а подписи `+3д` — отклонение даты окончания. **«Отменить» / «Повторить»** возвращают изменения в пределах текущего сеанса.
7. **«Экспорт» → PDF / PowerPoint** сохраняет дорожную карту. В PowerPoint элементы можно редактировать. Длинные карты автоматически делятся на страницы по периодам и задачам.
8. **«Сохранить копию»** скачивает `.roadly.json`: это резервная копия, которую можно снова открыть в Roadly через **«Открыть копию»**. На телефоне эти действия находятся под картой.

Экспорт фиксирует текущую версию плана. Анимация и автоматический пересчёт зависимостей работают внутри Roadly.

### Как двигаются задачи

Для цепочки **1 → 2 → 3 → 4**, если вставить трёхдневную задачу **5** после **1**, получится **1 → 5 → 2 → 3 → 4**. Без свободных промежутков задачи **2, 3 и 4** начнутся на три дня позже. Если между задачами был запас времени, он сначала используется. Независимые задачи сохраняют свои даты.

Связь означает «начать после завершения». При нескольких предшествующих задачах нужно дождаться всех. Циклические связи запрещены. Удаление задачи соединяет её предшественников с последующими задачами.

### Сохранение и ограничения первой версии

- Текущая карта автоматически сохраняется в этом браузере. Очистка данных браузера, приватный режим, другой браузер или другое расположение локального HTML-файла могут изменить доступность сохранённой карты. Регулярно скачивайте редактируемую копию.
- Одновременно открыт один проект; несколько проектов можно хранить отдельными `.roadly.json` файлами.
- Сроки считаются в **календарных днях**, включая выходные. Праздники и рабочие календари пока не учитываются.
- До 80 задач и трёх лет на карте, включая базовый план. Даты между 2000 и 2100 годами.
- Язык интерфейса и подписей экспорта переключается. Введённые пользователем названия задач и проектов не переводятся автоматически.
- Совместное редактирование, облачная синхронизация, напоминания и подключение к другим системам пока не реализованы.
- При включённой в системе настройке уменьшения движения анимация отключается.

## Открытие через GitHub Pages

Готовая сборка находится в папке `docs/`. После загрузки этих файлов в репозиторий включите сайт через веб-интерфейс GitHub:

1. Откройте [Settings → Pages](https://github.com/XXVLXD/pmwork/settings/pages).
2. В блоке **Build and deployment** выберите **Source: Deploy from a branch**.
3. Выберите ветку **main** и папку **/docs**, затем нажмите **Save**. Папка `/docs` содержит готовую сборку; корневой `index.html` предназначен для разработки.
4. Дождитесь завершения публикации. В **Settings → Pages** появится адрес и кнопка **Visit site**. Для стандартной конфигурации ожидаемый адрес — `https://xxvlxd.github.io/pmwork/`; он станет рабочим только после успешной публикации.

Страница приложения будет доступна по опубликованному адресу. Созданные в ней карты сохраняются локально в браузере. Для переноса карты из локального HTML в опубликованную версию используйте «Сохранить копию» и «Открыть копию» — у этих способов открытия разные хранилища браузера.

Наличие GitHub Pages зависит от настроек и тарифа репозитория. Если раздел Pages недоступен, не меняйте видимость репозитория ради этих шагов без отдельного решения. В текущей облачной среде чтение настроек через GitHub API ограничено; публикация и адрес сайта пока не подтверждены.

Исходники находятся в корне репозитория, готовая сборка для сайта — в `docs/`, архивы для скачивания — в `downloads/`. Для обновления готовых файлов после изменения исходников выполните `npm run pages:prepare` и сохраните обновлённые файлы вместе с исходниками.

## Для разработки

Node.js 22.12+; проверено на Node.js 24.19.0. Секреты, аккаунты и внешняя база данных не нужны. Используйте существующий checkout; облачная задача уже изолирована, отдельный Git worktree не требуется.

```sh
cd /workspace/pmwork
export npm_config_cache=/workspace/.cache/npm
npm ci
npm run dev
```

Сервер разработки использует порт 5173. Процесс нужно запускать заново после восстановления облачной среды; установленные зависимости и сборка сохраняются как файлы.

```sh
npm test
npm run build
npm run test:e2e
npm run package
```

`npm run build` проверяет TypeScript и создаёт автономный `dist/index.html`. Все скрипты, стили и шрифты встроены. `npm run package` создаёт `release/Roadly.html`, инструкцию, уведомления о лицензиях и архив `release/Roadly.zip`.

Браузерные проверки используют Chromium из `/usr/bin/chromium`; можно задать `CHROMIUM_PATH`. Для проверки содержимого экспортов нужны `pdftotext` и `unzip`, уже имеющиеся в этой облачной среде.

Проверки покрывают вставку в цепочку, параллельные задачи, запас времени, объединение зависимостей, удаление, циклы, даты, импорт и разбиение экспорта на страницы. Браузерные сценарии проверяют фактические промежуточные положения анимации, перетаскивание, клавиатуру, отмену, сохранение, языки, PDF/PPTX, адаптивную верстку и автономную сборку без сети.

Облачный Chromium запрещает навигацию `file://` административной политикой. Только эта проверка помечается пропущенной; автономная HTML-сборка отдельно проверяется через локальный HTTP с последующим отключением сети. Прямое открытие файла на компьютере пользователя требует проверки в его браузере.

## Технологии и лицензии

React, TypeScript, Vite; экспорт PDF — jsPDF, PPTX — PptxGenJS; иконки — Lucide; интерфейс — Manrope; встроенный PDF-шрифт — DejaVu Sans с поддержкой кириллицы. Уведомления о сторонних лицензиях формируются в `dist/THIRD_PARTY_NOTICES.txt` при сборке и включаются в архив.
